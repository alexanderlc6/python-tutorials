1.Device-related data
Rabbit MQ routing strategy
• Exchange: <BRAND>.master-data
• Exchange type: direct
• Routing key: <BRAND>
The following example illustrates a fictional inverter brand called 'inverterbrand':
• Exchange: inverterbrand.master-data
• Routing key: inverterbrand

integer, required

• acVoltageMax: Maximum value of the AC side voltage range, in V
integer, required
• installationDate: Date of device installation, in YYYY-MM-DD format, required
• removalDate: The date the device was removed, formatted as YYYY-MM-DD. Optional.
• address: location object, optional
o country: 2-character ISO 3166 code for the country
String, optional (default: HU)
o zipCode: Postal code of the address.
String, required
o city: Name of the city.
String, required
o landRegistryNumber: Identifier used in the land registry, also known as the parcel

street: Name of the street.
String, required
o streetType: Type of the street (e.g., Street, Avenue, Boulevard). The value set is

String, optional

String, optional

building: Building number or identifier. String, optional

Within the master data, certain fields of the Address object are mandatory.
Required fields: zipcode, city, street
If the exact address information is not available at the manufacturer’s side, the following 
default values may be used to fulfill the mandatory field requirements:
o zipcode: "0000"
o city: "unknown"
o street: "unknown"
All other mandatory master data fields (e.g. brand, model, nominal power) must still be 
populated according to the specification.


2. Measurement data
Rabbit MQ routing strategy
Exchange: <BRAND>. measurement-data
Exchange type: direct
Routing key: <BRAND>

Message format:

{
	"messageId": "67231151-ea92-4efe-a0a9-e7604669dc09",
	"serialNumber": "21231e32132eqw21312312",
	"readOutTs": "2024-11-18T15:50:32Z",
	"obisCode": "9.7.0",
	"data": [{
			"timestamp": "2024-11-18T15:20:44Z",
			"value": "150"
		},
		{
			"timestamp": "2024-11-18T15:25:14Z",
			"value": "154"
		}
	]
}

Field explanation:
• messageId: Unique identifier for the message. Version 4 UUID.
string, required
• serialNumber: Serial Number of the inverter
string, required
• readOutTs: The timestamp of when the data was read out for the device, in ISO 8601 
format. Required
• obisCode: The Obis code assigned by the measurement data
string, required
• data: An object containing the measurement data with the following values:
o timestamp: The timestamp of when the data was recorded, in ISO 8601 format. 
Required
o value: The actual value of the measurement data, measured by the inverter.
string, Required
Separator: Decimal point
Precision: 4 decimal places
Formatting rule: Values must be truncated after the fourth decimal place without 
rounding.
In theory, the array can contain up to 10.000 measurement records. Any additional entries 
beyond this limit will not be processed. In practice, since the 5-minute measurement data must 
be submitted at least once per hour, even in the worst-case scenario, the expected number of 
records per submission is 12. Please note, the long-term goal is to achieve a near real-time data 
transmission.
